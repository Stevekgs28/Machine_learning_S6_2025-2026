\begin{abstract}
This report presents our Machine Learning project on the \emph{Global Cybersecurity Threats 2015--2024} Kaggle dataset (3\,000 incidents, 10 features). The objective is to predict whether a cybersecurity incident results in \emph{high financial impact} (binary classification at the 75th percentile of financial loss). After training and comparing six models---including baseline, logistic regression, decision tree, random forest, soft voting, and stacking---all converging to an F1 macro of approximately 0.49 and a ROC-AUC near 0.50, we conducted a rigorous statistical diagnostic. This diagnostic demonstrates that the dataset carries no exploitable signal: \texttt{Financial Loss} follows a uniform distribution ($p_\text{KS} = 0.804$), no feature exhibits meaningful mutual information or association with the target, and direct regression yields negative $R^2$ on the test set. We validate our pipeline on a real-world phishing dataset where it achieves F1 macro above 0.85, confirming that our methodology is sound. The project covers the complete ML lifecycle including feature engineering, model comparison, SHAP-based interpretability, Docker deployment via FastAPI, and MLflow experiment tracking.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% =============================================================================

This report documents our Machine Learning project for the MOD10 course (Winter 2026). The objective is to apply the complete model-building lifecycle---from data preprocessing and exploratory data analysis, through model training and evaluation, to deployment and performance tracking---on a real-world problem.

We selected the \emph{Global Cybersecurity Threats 2015--2024} dataset available on Kaggle, which contains 3\,000 cybersecurity incidents described by 10 columns: country, year, attack type, target industry, financial loss (in millions USD), number of affected users, attack source, security vulnerability type, defense mechanism used, and incident resolution time (in hours).

We define the prediction task as a \textbf{binary classification}: predicting whether the financial loss exceeds the 75th percentile of the observed distribution, i.e., \texttt{Financial Loss} $\geq 75.63$\,M\$. This yields a target variable \texttt{High Financial Impact} with a 75/25 class split (2\,249 incidents in class~0, 751 in class~1).

\section{Feature Engineering and Exploratory Data Analysis}
\label{sec:eda}
% =============================================================================

\subsection{Data Preprocessing}

Our preprocessing pipeline (\texttt{code/preprocess.py}) performs the following operations:

\begin{enumerate}[leftmargin=2cm]
    \item \textbf{Unknown value normalization}: all textual entries matching common missing-value tokens (\texttt{Unknown}, \texttt{N/A}, \texttt{none}, \texttt{null}, etc.) are unified into a single \texttt{Unknown} category.
    \item \textbf{Type casting}: explicit conversion of \texttt{Year}, \texttt{Financial Loss}, \texttt{Number of Affected Users}, and \texttt{Incident Resolution Time} to numeric types.
    \item \textbf{Data quality report}: automatic detection of duplicates, missing values, and categorical cardinality.
\end{enumerate}

The quality report on our dataset reveals: zero duplicates, zero missing values after normalization, and 768 \texttt{Unknown} values concentrated on \texttt{Attack Source} ($\approx$25\%). Categorical cardinalities are moderate: \texttt{Country}=10, \texttt{Attack Type}=6, \texttt{Target Industry}=7, \texttt{Attack Source}=4, \texttt{Security Vulnerability Type}=4, \texttt{Defense Mechanism Used}=5.

\subsection{Target Construction}

We derive a binary target \texttt{High Financial Impact} by thresholding \texttt{Financial Loss} at the 75th percentile (75.63\,M\$). The resulting class distribution is 75/25 by construction (2\,249 class-0, 751 class-1).

\subsection{Feature Engineering}

The function \texttt{add\_feature\_engineering\_columns()} in \texttt{preprocess.py} creates the following domain-driven features to enrich the input space:

\begin{enumerate}[leftmargin=2cm]
    \item \textbf{Users Per Resolution Hour}: ratio of affected users to resolution time, capturing incident severity density.
    \item \textbf{Attack Source Is Unknown}: binary indicator for whether the attack source is unknown.
    \item \textbf{Year Bucket}: discretization of the year into three periods (2015--2018, 2019--2021, 2022--2024) to capture temporal trends.
\end{enumerate}

Note: loss-based features (\texttt{Loss Per 1k Users}, \texttt{Loss Per Resolution Hour}) are \textbf{excluded} from the classification pipeline to avoid target leakage, since the target derives from \texttt{Financial Loss} itself.

\subsection{Exploratory Data Analysis}

Our EDA (\texttt{code/diagrams.py}, \texttt{code/main.py}) produces the following key visualizations:

\begin{itemize}[leftmargin=2cm]
    \item \textbf{Class balance plot}: confirms the 75/25 split of \texttt{High Financial Impact}.
    \item \textbf{High-impact rate by category}: bar charts showing the rate of class-1 per modality of \texttt{Target Industry} and \texttt{Country}. Visual inspection suggests rates hovering near the baseline 25\% across all categories---an early warning sign of absent signal.
    \item \textbf{Numeric distributions}: histograms for \texttt{Year}, \texttt{Number of Affected Users}, and \texttt{Incident Resolution Time} showing approximately uniform distributions.
    \item \textbf{Correlation heatmaps}: Pearson correlation among numeric features and Cram\'er's V among categorical features, both revealing no noteworthy association with the target.
\end{itemize}

These EDA findings already suggest the absence of a predictive signal, a hypothesis formally tested in Section~\ref{sec:diagnostic}.

\section{Model Training and Comparison}
\label{sec:training}
% =============================================================================

\subsection{Candidate Models}

We compare six models spanning a range of complexity levels. All non-trivial models are tuned via \texttt{GridSearchCV} with \texttt{StratifiedKFold(n\_splits=5)} cross-validation, optimizing F1 score on the positive class. \texttt{class\_weight="balanced"} is used systematically to compensate for the 75/25 class imbalance.

\begin{enumerate}[leftmargin=2cm]
    \item \textbf{Baseline} (\texttt{DummyClassifier(strategy="most\_frequent")}): performance floor.
    \item \textbf{Logistic Regression}: linear model with L2 regularization. Hyperparameter grid: $C \in \{0.01, 0.1, 1, 5, 10, 20\}$, solver = \texttt{lbfgs}.
    \item \textbf{Decision Tree}: non-linear model capturing interactions. Grid: \texttt{max\_depth} $\in \{3,5,8,12,16\}$, \texttt{min\_samples\_split} $\in \{2,5,10,20\}$, \texttt{min\_samples\_leaf} $\in \{1,3,5,10\}$, \texttt{ccp\_alpha} $\in \{0, 0.0005, 0.001, 0.005\}$.
    \item \textbf{Random Forest}: ensemble of trees. Grid: \texttt{n\_estimators} $\in \{50,100,200\}$, \texttt{max\_depth} $\in \{\text{None},10,20\}$, \texttt{min\_samples\_split} $\in \{2,5,10\}$, \texttt{min\_samples\_leaf} $\in \{1,2,4\}$.
    \item \textbf{Soft Voting} (ensemble): combines tuned Logistic Regression and Decision Tree with soft voting (probability averaging).
    \item \textbf{Stacking} (ensemble): uses tuned Logistic Regression and Decision Tree as base learners, with a balanced Logistic Regression as the meta-learner, using \texttt{predict\_proba} stacking method and 5-fold cross-validation.
\end{enumerate}

Each model is wrapped in a scikit-learn \texttt{Pipeline} containing a \texttt{ColumnTransformer} preprocessing step that applies median imputation and optional standard scaling to numeric features, and one-hot encoding to categorical features.

\subsection{Ensemble Methods Analysis}

Both ensemble techniques fail to improve upon the individual models:

\begin{itemize}[leftmargin=2cm]
    \item \textbf{Soft Voting} (test F1 = 0.4814): averaging the probabilities of two models that individually predict at chance level yields a combined prediction that is also at chance level. Ensemble methods amplify signal---when no signal exists, there is nothing to amplify.
    \item \textbf{Stacking} (test F1 = 0.4792): the meta-learner receives probability outputs from two uninformative base models. Training a logistic regression on noise features produces noise predictions. The low train--test gap (0.009) reflects that the stacking meta-learner has ``learned'' to produce near-constant predictions---a form of underfitting that mirrors the dataset's lack of structure.
\end{itemize}

This signature---sufficient model capacity combined with chance-level generalization for all model families, including ensembles---suggests that the problem lies with the \emph{data}, not the models: there is simply no exploitable signal in the features to predict the target. This hypothesis is rigorously tested in Section~\ref{sec:diagnostic}.

\section{Evaluation Metrics}
\label{sec:metrics}
% =============================================================================

We report a comprehensive set of classification metrics to provide a multi-faceted view of model performance.

\subsection{Metrics Overview}

\begin{itemize}[leftmargin=2cm]
    \item \textbf{Accuracy}: proportion of correct predictions. Misleading under class imbalance: predicting the majority class always gives 75\% accuracy.
    \item \textbf{Precision (macro)}: average per-class precision, measuring the proportion of positive predictions that are correct.
    \item \textbf{Recall (macro)}: average per-class recall, measuring the proportion of actual positives correctly identified.
    \item \textbf{F1 macro}: harmonic mean of precision and recall, averaged equally across classes. Our \textbf{primary metric}, as it penalizes a model that ignores the minority class.
    \item \textbf{ROC-AUC (One-vs-Rest)}: area under the receiver operating characteristic curve, measuring the model's ability to rank positive samples above negative ones. A value of 0.50 indicates no discriminative ability.
\end{itemize}

\section{Dataset Diagnostic}
\label{sec:diagnostic}
% =============================================================================

Faced with flat performance across three model families and two ensemble approaches, we formulate four competing hypotheses and test each systematically.

\subsection{Four Hypotheses}

\begin{description}[leftmargin=2cm]
    \item[H1 --- Insufficient model capacity.] The algorithms are not expressive enough to capture the feature--target relationship.
    \item[H2 --- Inadequate preprocessing.] Our pipeline destroys relevant information (encoding, scaling, etc.).
    \item[H3 --- Individually uninformative features.] No single feature carries information about the target.
    \item[H4 --- Structurally random dataset.] The target is independent of the features by construction.
\end{description}

H1 and H2 are \emph{already partially refuted} by the results in Section~\ref{sec:training}: the non-linear Random Forest has sufficient capacity (train F1 = 0.91), and our pipeline follows standard scikit-learn best practices. We validate H3 and H4 explicitly below.

\subsection{H3 --- Mutual Information on Numeric Features}

We compute the mutual information between each numeric feature (excluding the target and \texttt{Financial Loss} from which the target derives) and the binary target. Results are in Table~\ref{tab:mi} and Figure~\ref{fig:mi}.

\midrule

\begin{figure}[H]

A mutual information of 0 means that knowing the feature provides literally zero reduction in uncertainty about the target. Two of three numeric features are exactly at 0, and the third (0.006) is far below the 0.02--0.05 reference thresholds in the literature. H3 is confirmed for numeric features.

\subsection{H4 --- Distribution of Financial Loss}

The absence of signal in the features led us to examine the distribution of the source variable \texttt{Financial Loss}. Figure~\ref{fig:loss} presents the observed histogram alongside the theoretical density of a uniform distribution on $[0.50, 99.99]$.

\begin{figure}[H]
\centering
\includegraphics[width=0.92\linewidth]{graphs/01_loss_distribution.png}
\caption{Distribution of \texttt{Financial Loss} (3\,000 incidents). The observed density closely follows a uniform distribution on $[0.50, 99.99]$. The Kolmogorov--Smirnov test gives $D = 0.012$ and $p = 0.804$: uniformity cannot be rejected.}
\label{fig:loss}
\end{figure}

The empirical mean is 50.49, the median 50.80, the standard deviation 28.79---exactly matching the theoretical values for a uniform on $[0.5, 100]$ (expected $\sigma = 99.5/\sqrt{12} \approx 28.72$). The Kolmogorov--Smirnov test against this uniform gives $D = 0.0117$, $p = 0.804$: \textbf{the hypothesis that \texttt{Financial Loss} follows a uniform random distribution cannot be rejected.}

\subsection{Validation by Direct Regression}

A final objection might be that the quantile-based binarization destroys a signal that exists in the continuous \texttt{Financial Loss} values. We test this hypothesis by directly regressing the continuous value (\texttt{code/diagnostic\_regression.py}). Results are in Table~\ref{tab:regression}.

The test $R^2$ is \emph{negative} for both models, meaning their predictions are statistically \emph{worse} than a constant model predicting the training mean. The Random Forest again memorizes the training set ($R^2_\text{train} = 0.855$) but produces negative $R^2$ on test, confirming the same pattern as classification. This locks H4: it is not the binarization that destroys the signal---the signal simply \emph{does not exist} in this dataset.

\subsection{Pipeline Validation on a Real Dataset}

To confirm our pipeline is correct and the poor performance stems solely from the dataset, we applied the exact same code to a real-world cybersecurity dataset: \emph{PhishingWebsites} from OpenML (11\,055 URLs, phishing vs. legitimate). Figure~\ref{fig:pivot} compares the results.

\subsection{Diagnostic Summary}

All tests converge to a single conclusion: the \emph{Global Cybersecurity Threats 2015--2024} dataset behaves, for the task we considered, as an \textbf{independent random draw}.

\begin{itemize}[leftmargin=2cm]
    \item \texttt{Financial Loss} follows a uniform distribution on $[0.5, 100]$ ($p_\text{KS} = 0.80$), typical of a \emph{synthetic dataset} generated by uniform sampling rather than observed data.
    \item No numeric feature carries measurable mutual information with the target (max 0.006).
    \item No categorical feature exhibits significant association with the target (Cram\'er's V $\leq 0.058$, $\chi^2$ $p$-value $\geq 0.34$).
    \item Direct regression on the continuous value yields negative $R^2$ on test for both linear and non-linear models.
    \item Our pipeline achieves F1 macro $> 0.85$ on a real dataset, confirming the code is correct.
\end{itemize}

No machine learning model, regardless of complexity, can \emph{in principle} outperform the majority-class baseline on this dataset for this task: there is no information to learn.

\subsection{Interpretation}

On a dataset with genuine signal, SHAP analysis typically reveals 1--3 dominant features concentrating most of the importance. Here, the importance is \emph{diluted} across dozens of one-hot encoded features, none exceeding a mean $|\text{SHAP}|$ of 0.02. This pattern is exactly what one would expect when the model is fitting noise rather than signal---the Random Forest distributes splits across random features, each contributing negligible SHAP importance.

This SHAP analysis provides \textbf{independent confirmation} of the diagnostic conclusions: the model has no meaningful features to rely on for its predictions.

\section{Deployment with Docker}
\label{sec:deployment}
% =============================================================================

\subsection{REST API with FastAPI}

We built a REST API using FastAPI (\texttt{code/api.py}) to serve real-time predictions. The API exposes three endpoints:

\begin{itemize}[leftmargin=2cm]
    \item \texttt{GET /health}: returns the service status and whether a model is loaded.
    \item \texttt{GET /}: root endpoint listing available endpoints.
    \item \texttt{POST /predict}: accepts incident features as JSON and returns the predicted class (0 or 1), a human-readable label (``Standard Impact'' or ``High Financial Impact''), the probability of high impact, and a disclaimer noting the model is trained on a dataset without exploitable signal.
\end{itemize}

The API loads the serialized best model (\texttt{best\_model.joblib}) at startup and applies the same feature engineering pipeline used during training. The \texttt{/predict} endpoint accepts input conforming to the \texttt{IncidentInput} Pydantic schema with fields for country, year, attack type, target industry, number of affected users, attack source, vulnerability type, defense mechanism, and resolution time.

\section{Discussion and Conclusion}
\label{sec:discussion}
% =============================================================================

\subsection{Methodological Takeaways}

Our work illustrates a skill that is often under-taught but essential in practice: \textbf{knowing when machine learning is not the right tool}. Flat performance across multiple models is not a fatality to accept or a signal to add more features and increase capacity---it is a signal to \emph{investigate}.

The diagnostic instrumentation we deployed (Kolmogorov--Smirnov test, mutual information, Cram\'er's V, $\chi^2$ tests, Wald confidence intervals per modality, regression verification) is reusable as-is on any future dataset and constitutes a ``diagnostic toolkit'' to apply \emph{before} investing time in hyperparameter tuning.

\subsection{Conditions for Feasibility}

Our pipeline is deliberately \emph{dataset-agnostic}: \texttt{preprocess.py} and \texttt{training\_comparison.py} accept any CSV with numeric and categorical columns and adapt automatically. To apply the same methodology to a signal-bearing dataset, one would need to:
\begin{enumerate}[leftmargin=2cm]
    \item Select a real (rather than synthetic) dataset---recognized candidates for intrusion detection include NSL-KDD, UNSW-NB15, and CICIDS2017.
    \item Run \texttt{diagnostic\_signal.py} as a preliminary step to confirm the presence of signal.
    \item Execute the same \texttt{training\_comparison.py} to compare models.
\end{enumerate}

\subsection{Limitations}

Our conclusion applies to the specific task of predicting \emph{High Financial Impact} on \emph{this particular} dataset. It remains possible that other formulations (unsupervised clustering, anomaly detection on specific sub-populations) could reveal structures we have not explored. Nonetheless, our work rigorously validates that the supervised classification task as originally defined is intrinsically infeasible on this data.

\subsection{Conclusion}

We applied a standard machine learning pipeline---preprocessing, feature engineering, model comparison, cross-validation, hyperparameter tuning, ensemble methods, SHAP interpretability, Docker deployment, and MLflow tracking---to a Kaggle cybersecurity dataset. Faced with the convergence of all six model families toward an AUC of 0.50, we did not attempt to optimize meaningless metrics but instead conducted a \textbf{rigorous statistical diagnostic}, which demonstrates that the dataset carries no exploitable signal for the chosen task.

This result is, in itself, a methodological contribution: identifying that a problem is \emph{structurally infeasible} given the available data is a competency as important as optimizing a model when it is possible. Our diagnostic pipeline is reusable, and our modeling pipeline has been validated on a real dataset where it achieves state-of-the-art performance.
